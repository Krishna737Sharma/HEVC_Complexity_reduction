# ETH-CNN: A Deep Learning Approach for HEVC Intra-CU Partitioning

This repository contains the implementation of a CNN-based model (ETH-CNN) for predicting Coding Unit (CU) partitioning in HEVC (High Efficiency Video Coding) intra-mode. The goal is to reduce the computational complexity of the HEVC encoding process by using a deep learning model to predict the optimal CU split decisions ahead of the traditional, exhaustive rate-distortion optimization process.

The project is divided into three main parts:
1.  **Data Preprocessing**: Scripts to convert raw YUV video files and CU depth information into a structured binary format for efficient training.
2.  **Model Training**: The main script to define, train, and validate the ETH-CNN model using PyTorch.
3.  **Model Evaluation**: A script to test the trained model on an unseen dataset and report its performance.

## Data Structure Explained

The core of this project relies on a custom binary data format (`.dat`) that is generated by `data_preprocessing.py`. This format is designed for efficient reading and batching during training.

Each sample in the `.dat` file is a fixed-size block of **4992 bytes**. Here is the breakdown of a single sample:

| Byte Range             | Size (Bytes) | Description                                                                                                                                                                                                                         | Data Type |
| ---------------------- | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| **0 - 4095** | 4096         | The raw pixel data for a **64x64 luma (Y) block**, flattened into a 1D array. This is the primary input feature for the CNN.                                                                                                            | `uint8`   |
| **4096 - 4159** | 64           | **Padding/Unused Space**. This block is reserved but not used in the current model.                                                                                                                                                 | `uint8`   |
| **4160 - 4991** | 832          | **CU Depth Labels for all QP values**. This block contains the ground truth CU partition information. It is structured to hold labels for 52 possible Quantization Parameter (QP) values (from 0 to 51). Each QP has a 16-byte label. | `uint8`   |

### How Labels are Extracted

The model is trained on a specific set of QPs: `[22, 27, 32, 37]`. During data loading, the `StreamingDataset` class randomly selects one of these QPs for each sample.

The label for a chosen `QP` is extracted from the 832-byte label block using the following logic:
1.  **Calculate Offset**: The starting position of the label is found at `4160 + (QP * 16)`.
2.  **Read Label**: 16 bytes are read from this starting position.
3.  **Interpret Label**: These 16 bytes represent the CU depth for each of the sixteen 16x16 sub-blocks within the 64x64 CTU. The values indicate how each 16x16 block is partitioned (e.g., 0 for 64x64, 1 for 32x32, 2 for 16x16, 3 for 8x8).

This structure allows a single data sample to contain the labels for all possible QPs, making the data generation and loading process highly efficient.

## Workflow

The end-to-end process is as follows:

### 1. Data Generation and Preprocessing

The `data_preprocessing.py` script reads raw YUV video files and their corresponding `CUDepth.dat` files (which contain the ground truth partitioning information from an actual HEVC encoder).

-   It iterates through each frame of a video.
-   For each 64x64 CTU in a frame, it creates a **4992-byte sample** as described in the "Data Structure" section.
-   The luma (Y) component of the CTU is written as the first 4096 bytes.
-   The CU depth information for each QP is written into its designated 16-byte slot within the label block.
-   All generated samples are concatenated into large binary files (e.g., `AI_Train_...dat`).
-   Finally, the samples within these files are shuffled to ensure randomness during training.

### 2. Model Training

The `ETH_CNN.py` script handles the training process.

-   **Data Loading**: The `StreamingDataset` class reads the shuffled `.dat` files. It efficiently seeks to the position of a required sample, reads the 4992-byte block, and parses the image and label.
-   **Hierarchical Labels**: The 16-byte CU depth label is converted into three hierarchical binary labels for predicting splits at the 64x64, 32x32, and 16x16 levels.
-   **Model Architecture**: The ETH-CNN model takes the 64x64 luma block and the selected QP value as input. It uses a multi-branch architecture to extract features at different scales and feeds them into three separate output heads, one for each partitioning level (64, 32, 16).
-   **Training Loop**: The script uses a standard PyTorch training loop with an SGD optimizer and an ExponentialLR scheduler. It calculates a custom loss (`custom_repo_loss`) that combines the binary cross-entropy losses from the three hierarchical levels.
-   **Validation & Checkpointing**: After each epoch, the model is evaluated on a validation set. The best-performing model is saved as a checkpoint (`.pth` file). The process includes early stopping logic and dynamically refreshes the training data subset to improve generalization.
-   **Experiment Tracking**: The script is integrated with `wandb` (Weights & Biases) to log metrics like loss, accuracy, and learning rate.

### 3. Model Evaluation

The `Model_Evaluation_ETH_CNN.py` script is used to assess the final performance of the trained model.

-   It loads the best model checkpoint saved during training.
-   It runs the model on the unseen test dataset (`AI_Test_...dat`).
-   It calculates and prints the final accuracy and loss for each partitioning level (64x64, 32x32, and 16x16).

## Usage

### Step 1: Prepare the Data

1.  Place your raw YUV video files and corresponding CU Depth info files in separate directories.
2.  Open `data_preprocessing.py` and modify the paths for `YUV_PATH_ORI` and `INFO_PATH`.
3.  Run the script:
    ```bash
    python data_preprocessing.py
    ```
    This will generate the shuffled `.dat` files for training, validation, and testing.

### Step 2: Train the Model

1.  Open `ETH_CNN.py`.
2.  Update the `train_file_path` and `validation_file_path` variables to point to the `.dat` files you generated.
3.  Log in to your Weights & Biases account if you want to track the experiment:
    ```bash
    wandb login
    ```
4.  Run the training script:
    ```bash
    python ETH_CNN.py
    ```
    The script will start training and periodically save checkpoints. The best model will be saved as `best_model_4qp_parallel_data_processing_loss_mod.pth`.

### Step 3: Evaluate the Model

1.  Open `Model_Evaluation_ETH_CNN.py`.
2.  Ensure the `test_file_path` points to your test dataset.
3.  Make sure the `checkpoint_path` variable is set to the name of your best saved model.
4.  Run the evaluation script:
    ```bash
    python Model_Evaluation_ETH_CNN.py
    ```
    The final test accuracy and loss will be printed to the console.
